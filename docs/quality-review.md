## 二、P0：直接影响用户信任（必须先修）

### P0-1　C1/C2 里大量"词条"根本不是西语词

**实测抽样**（`js/data/books.js`）：

- C2 段（自 line 15846 起）：
  `six`(六)、`beacon`(信标)、`scarlet`(猩红色)、`marshals`(法警) —— **英文词**；
  `aproveché`、`creará`、`convertía`、`anunciando`、`casando`、`escucharas` —— **动词变位/副动词**；
  `cuídalo`、`págale`、`veámoslo`、`afeitarse` —— **命令式/不定式+代词**。
- C1 段（line 8988 附近）：
  `masters`（英文）、`observen`（虚拟式）、`torcido`、`encendió`、`denunció`、`negociando`；
  `iraq`、`igor`、`cox`、`shiva`、`amazonas` —— **专名**。

**规模（决定性）**：
- C2 共 9,646 词，其中**手编高质量词条仅 12 条**（`ineludible`/`epítome`/`ubicuo`/`diafano`/`prosopopeya` 等，带 IPA+例句），**其余 9,634 条全部是脚本灌入**，且 9,634 条无例句。
- C1 共 6,965 词，6,806 条无例句。
- 抽样中"不可用作词汇条目"的比例约占一半以上（变位/专名/英文词/黏着代词）。

**用户实际感受**：进入「C2 母语级精微 · 文学与高阶文本中的精微词」，翻两屏就开始出现 `six`、`beacon`。

**建议**：整段回滚 C2 注入块（保留 12 条手编），C1/B2 走删除 pass（**须先加固 `clean-nonwords.mjs` 的 `[^}]*` 正则**，否则会截断含 `}` 的条目，历史上已出过事故）。

### P0-2　中文释义损坏与乱码

**实测**：

| 词条 | 现有释义 | 应为 |
|---|---|---|
| `bendito` | 迷迭香 | 神圣的 / 有福的 |
| `mocoso` | 窃笑 | 流鼻涕的（小鬼） |
| `bronceado` | 新清 | 晒黑的 |
| `juerga` | 聚会通知 | 狂欢 / 玩乐 |
| `cuota` | `éé¢`（乱码） | 配额 |
| `complot` | 绘图 | 阴谋 |

- 自动化自查：B2 段**损坏 67 条**（无中文字符 33 / Latin-1 残留 8 / 标点残留 26）。
- **判据盲区**：`data-lint.mjs` 的「释义可疑」自报为 **0**，抓不到这类错误——修复前必须先扩这条判据。

**影响**：直接教错中文，比缺例句更严重。

### P0-3　C1/C2 几乎无例句，导致核心练习退化为无意义题

**实测**（`js/modules/learn.js:1878-1882`）：

```js
const own = w.ex || ((findEntry(w.word) || {}).ex) || '';
const sent = own || (corpus.sentenceWith(w.word) || {}).es || '';
const src = sent || `${w.word} es una palabra.`;   // ← 兜底句
prompt: { sentence: blankWord(src, w.word) },
```

- 无例句时，完形填空题干退化成 **「`_____ es una palabra.`」**——挖空位置恒定、句子零信息量。
- 认词卡（`learn.js:611-615`）则退化为只显示「怎么读」提示，用户会觉得"内容不全"。

**影响面**：C1 6,806 + C2 9,634 = **16,440 个词**的完形练习无效。

**建议**：短期在 UI 层对"无例句词"降级处理（明确提示"该词暂无例句"而非给假题）；中期补 C1 例句，或先隐藏 C1/C2。

## 三、P1：体验明显受损

### P1-1　词书库不披露例句覆盖率 / 内容可信度
`learn.js:515-538` 的卡片只显示「词数 + 描述 + 进度」。用户**无法预知**打开 C2 会掉进坑里。
建议：卡片加一行「例句覆盖 2%」这类真实指标；覆盖率过低的词书置灰或标注「施工中」。

### P1-2　首屏性能
- `standalone.html` **2.58 MB**（`books.js` 1.86 MB 被内联）。
- `learn.js:4` 静态 `import { WORD_BOOKS }`，并在模块初始化时 `WORD_BOOKS.forEach(b => b.words.forEach(...))` 全量建索引（line 63/75）→ **启动即解析 25,379 个词对象**。
- `sw.js:32-42` 页面导航为 **network-first** → 在线用户**每次访问都重新下载 2.6 MB**（缓存只用于离线兜底）。

建议：词库按等级拆分为动态 `import()`；导航改 stale-while-revalidate。

### P1-3　发音门槛偏高
自然语音必须由用户自填 Azure / ElevenLabs 密钥（`index.html:66-87`），否则只有本地语音兜底。对普通学习者，"注册 Azure 拿 key"这一步流失率会很高。

### P1-4　没有分级测评，用户不知该选哪本
工作区里已有《词汇量测评开发规格》，但站内没有实现。6 本词书并列，新用户只能靠猜。现有「测评」子页只是"考学过的词"，不是 placement test。

1. **两个自动化方向相反，且在互相干扰**

2. **`run-pipeline.mjs` 在本机失效**：三步全部 `exit null`、无输出；但单独跑 `build-standalone.js` / `smoke.js` / `css-lint.js` 均正常（exit 0）。自动化第 7 步的校验会踩空。
3. **无 git / 无备份**：`books.js` 已被外部并发改写多次（最近 09-29 13:31:43），不可追溯。这是唯一的结构性保险缺口，也是所有"数据事故"无法回头的原因。
4. **发布就绪度**：`share/` 已齐备（`index.html` 2.58 MB + `manifest.webmanifest` + `sw.js` + 4 个图标），但与 `standalone.html` 同步——**发上去等于把 P0 内容问题一起发出去**。沙盒部署不稳（error 12809），建议 GitHub Pages。
